# Copyable prompt: create a new learning tree

```text
Use this repository as the implementation reference. Read AGENTS.md,
docs/create-with-codex.md, docs/data-format.md and docs/customization.md.
Use data/minimal-template.json as the structural template. Inspect the viewer
source as needed; do not copy the computer-science curriculum into another field.

Subject or interdisciplinary goal: [fill in]
Starting knowledge: [fill in]
Terminal outcome: [fill in]
Degree path, if relevant: [bachelor / master / doctorate / direct doctorate /
integrated graduate / custom]
Actual duration or milestone structure: [fill in or leave flexible]
Special interests: [fill in]
Desired language and depth: [fill in]
Public or private output: [public generic profile / private personalized tree]

Create a complete, rich and academically defensible tree. Include foundations,
subject knowledge, suitable methods, evidence production, communication and
practical milestones. Choose these for the subject, not from a fixed list of
computing methods. Ask only about material missing facts; do not repeat context
already supplied. Clearly state authoring assumptions.

For each node provide scope, a concrete observable outcome, necessary hard
prerequisites, optional related background, caveats and honest source scope.
Use primary public sources for specialized claims; distinguish titles/abstracts
from full text. Do not fabricate citations, universal degree rules or deadlines.

Every node must have a meaningful route from the stated start and toward the
goal. Solid prerequisites must be real, with multiple prerequisites meaning AND.
Use dashed development/application edges with explicit reasons for optional
branches and concrete outputs; do not turn all possible methods into mandatory
graduation prerequisites. Keep the combined directed graph acyclic.

Make stages and degrees match this request. Do not assume a separate master's
degree, a fixed doctoral length, a particular institution, or a publication quota.
Preserve privacy: public files must not contain real identities, advisors,
student IDs, credentials, private notes or machine-specific paths.

Write data/<new-stable-id>.json and build examples/<new-stable-id>.html with the
existing generic viewer. Keep subject and degree settings in data rather than
hard-coding the application. Validate structure and review specialized edges
when authorized; if checks are explicitly declined, use --skip-validation and
report that limit. Deliver the JSON, standalone HTML, source list and concise
assumptions. Do not publish or push unless requested.
```
